¿Qué es Git?
Es un sistema de control de versiones de código abierto y mantenimiento activo. Nos ayuda a rastrear y gestionar los cambios en el código del software a lo largo del tiempo
Una ventaja es que se puede trabajar de manera simétrica con la rama principal de trabajo sin afectar el flujo de trabajo actual y poder seguirlo modificando o
unificar la rama principal con la que se está trabajando. 

¿Qué es GitHub?
Es una plataforma que usa la base de Git para compilar software para el ciclo de vida de desarrollo de software. Consiste en 6 fases:

-Plan:Realice un seguimiento del trabajo, establezca hitos y organice proyectos a largo plazo.
-Create:Escribir y almacenar código, desarrollar nuevas características de forma segura y crear una escala de tiempo clara de los cambios.
-Review:Sugerir cambios en el proyecto, analizar las actualizaciones con los revisores y aplicar comentarios.
-Test:Automatice las comprobaciones para validar todos los cambios antes de combinarlos.
-Deploy:Envíe software con flujos de trabajo de implementación automatizados y administración de versiones.
-Operate:Supervise las aplicaciones, administre las dependencias y busque y corrija problemas de seguridad.

Diferencia entre Git vs GitHub
Git es el sistema de control de versiones como tal.
GitHub se basa en el software open source de Git, mediante repositorios en la nube, junto con herramientas de planeación y colaboración

¿Qué es un commit?
Es como un punto de guardado del estatus de un proyecto en cierto tiempo, parecido como el guardar en los videojuegos.
Es inmutable (no se puede modificar), tiene un identificador único o hash y contiene un mensaje descriptivo donde se detallan los cambios hechos.

¿Qué es un branch?
Va a ser una versión paralela de un código en el que se puede modificar, experimentar, adicionar o corregir errores sin que se afecte el funcionamiento de la rama principal

¿Qué es un Pull Request (PR)?
Es una solicitud para aplicar cambios en el código a una rama de un repositorio, donde se permite la revisión antes de la aplicación. Esto nos es útil porque se pueden revisar
cambios antes de que se pueda afectar al funcionamiento de la rama principal
